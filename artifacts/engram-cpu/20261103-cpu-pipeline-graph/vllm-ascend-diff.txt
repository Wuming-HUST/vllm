+## Experimental synchronous CPU lookup
+
+`AscendParallelEngramEmbedding.lookup_cpu(indices, out)` is an explicit host
+entry point for the paired vLLM `engram_cpu_C` extension. It does not change the
+default device lookup. It requires contiguous CPU INT32 global IDs and a
+contiguous, disjoint BF16 output `[tokens, padded_heads, dim]`. Weights and
+scales must remain in live CPU storage until the call returns. Device-resident
+tables are rejected rather than copied implicitly.
+
+The adapter passes the existing head and vocabulary shard offsets to the native
+operator. BF16, INT8/FP32 and native E4M3FN/E8M0 tables are supported; invalid
+IDs and padded output heads are zeroed. No table format conversion is performed.
+The optional extension is loaded only when this method is called and must be
+built against the installed PyTorch version. A missing extension raises an
+explicit error; no runtime JIT is used.
+
+The caller owns index D2H completion, pinned output storage, H2D, collectives and
+consumer events. CPU completion alone does not mean the NPU consumer is ready.
+The method is synchronous and must run outside graph capture. The optional model backend below manages stream-ordered transfers and callback
+ownership for model callers; this low-level host entry point remains synchronous.
+
+The optional `backend` keyword selects `auto`, `scalar`, `neon` or `sve2`;
+`prefetch_distance=0` disables read prefetch. Auto uses the NEON candidate on
+AArch64 when compiled and usable. The NEON code does not require BF16 hardware
+instructions. SVE2 is guarded by Linux capabilities and remains explicit for
+target comparison. These choices do not modify the model's TP/DP communication
+or device scheduling. The paired vLLM checkout contains
+`docs/contributing/model/engram_cpu_kunpeng.md` and
+`tools/validate_engram_cpu.py` for offline 920/950 validation.
+
+## Optional CPU producer/model backend
+
+With the paired modified vLLM checkout, set
+`--engram-config '{"cpu_offload":true,"lookup_backend":"cpu","cpu_kernel":"auto"}'`.
+This selects CPU vocabulary conversion, hash and embedding retrieval. Device
+remains the default. Eager execution is no longer mandatory.
+
+CPU hash consumes the runner's raw coordinates/history outside capture. The
+producer stream queues ID D2H, a native C++ host callback for gather/dequant,
+BF16 H2D, and the existing PCP/DP/TP path before layer-ready publication.
+Pinned buffers and callback tickets survive until copy retirement. Errors are
+checked before accepting model output. Metadata copies/hash still form a
+synchronous prefix; actual retrieval overlap is unmeasured here.
+
+CPU mode chooses the existing graph-external producer and keeps FULL consumer
+ExternalEvent waits/resets. It disables graph-internal CPU production, not the
+consumer graph. Supported tag topology restrictions remain unchanged. Native
+Ascend E8M0 semantics are preserved. CANN callback availability and stream queue
+ordering require target verification; there is no silent fallback.
+
+See paired vLLM `docs/contributing/model/engram_cpu_serving.md` for startup,
+rollback, lifecycle/parallel contracts, device callback graph tests and repeated
+checkpoint generation comparisons. No NPU/checkpoint acceptance was run here.
